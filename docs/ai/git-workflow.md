# Git 提交规范（AI 与协作者必读）

> 目标：**历史即文档**。每条提交应能独立解释"为什么改"，不保留中间脏态。

## 一、核心规则

1. **一条提交只做一件事**
   - 功能、重构、文档、构建产物分开提交
   - 同一功能的多步实现，合成为一条（除非中间态确有独立价值）

2. **禁止"修补型"提交堆积**
   - `fix: 上一个提交的笔误`、`fix: 补上遗漏的文件` 这类提交，
     在推送前必须 squash 进原提交
   - 判断标准：新提交是否只是让前一条提交"变正确"？是 → fixup

3. **每条提交都必须可构建**
   - 至少满足：`gofmt` 无差异、`go build ./...` 通过
   - 涉及配置/文档的提交：`just check` 通过

4. **提交前跑门禁**

   ```bash
   just check        # 结构 + lint + 测试
   script/ci.sh --full # 完整 CI（含 arm64 与双平台物料校验）
script/ci.sh --offline # 离线环境：跳过物料下载与依赖 bundle 的检查
   ```

5. **提交信息格式**

   ```
   <type>(<scope>): <subject>

   <body：为什么、影响面>
   ```

   | type | 用途 |
   |---|---|
   | `feat` | 新增能力 |
   | `refactor` | 行为不变的结构调整 |
   | `fix` | 修缺陷 |
   | `docs` | 只改文档 |
   | `chore` | 构建产物、依赖、工具配置 |

   `scope` 用目录或包名：`cli`、`checks`、`manifest`、`scaffold`、`docs`。

## 二、合并历史的操作方法

```bash
# 1. 查看待整理的提交
git log --oneline origin/master..HEAD

# 2. 交互式合并：把修补提交标为 fixup / squash
git rebase -i origin/master
#   pick   保留
#   fixup  并入上一条并丢弃本条的说明
#   squash 并入上一条并合并说明
#   reword 只改说明

# 3. 合并后必须验证
git diff <整理前的 sha> HEAD    # 树必须完全一致
just check && script/ci.sh --full
```

**整理前先建备份**：

```bash
git branch backup/pre-rewrite
```

确认无误后再删。

## 三、禁止事项

| 禁止 | 原因 |
|---|---|
| 提交 `test/.work/`、`bundle/`、`.cache/` | 构建产物，已 gitignore |
| 提交个人调试脚本（硬编码绝对路径） | 对他人无用，且泄露本地路径 |
| 一个提交里混入"格式化 + 功能" | review 无法分离 |
| 推送未验证的历史改写 | 影响他人；先本地 `just check` |

## 四、AI 提交时的额外要求

1. 提交前必须执行 `just check` 与相关测试，结果写入提交说明尾部
2. 改历史（rebase/squash）后必须验证 **树内容未变**
3. 不得为"修自己的笔误"新增提交，直接 fixup
4. 提交说明用中文描述"为什么"，代码/命令保持英文

## 提交合并方案（可复用）

适用于任意 Git 仓库。目标：消除"修补型"脏提交，保留有意义的迭代，不按功能粗暴合并。

### 1. 术语

| 术语 | 定义 |
|---|---|
| **功能提交** | 引入新能力或改变外部行为 |
| **迭代提交** | 推翻/替换旧实现的方案变更，有决策价值 |
| **修补提交（脏）** | 只为让前一条提交"变正确"：笔误、漏文件、紧随其后的 fix |
| **结构性重构** | 跨目录的命名、分层、迁移，影响面大但行为不变 |
| **生成物** | lock、校验和、产物清单等由工具写回的文件 |

### 2. 判定规则

| 对象 | 处理 |
|---|---|
| 同一功能的 review / 小重构 | 并入该功能提交 |
| 跨目录结构性重构 | 保留单个提交，不并入功能 |
| 功能实现阶段的中间提交 | 若后续被完全取代，可合并；若体现方案取舍，保留 |
| 修补提交 | 并入被修补的提交 |
| 缺陷修复 | 优先并入相关功能；无法归属则独立 |
| 文档 | 新方案/架构/里程碑保留；同文档细化并入里程碑 |
| 测试 | 与被测功能同批 |
| 生成物 | 跟随产生它的代码提交，不单独成提交 |
| 组件/依赖首次引入 | 强制保留，提交信息说明来源、基线与本地差异 |
| 回滚/还原 | 保留独立提交（它记录了决策） |

### 3. 操作流程

```text
1. 冻结：git branch backup/<name>，记录旧 HEAD
2. 建映射表：旧 SHA → 新提交 / 合并目标 / 理由 / 置信度
3. 评审映射表，只审被合并项
4. 在新分支重放（rebase fixup 或快照重建）
5. 校验：树差异、构建、CI
6. 推送：--force-with-lease；保留备份分支
```

映射表模板：

| 旧 SHA | 主题 | 新提交 / 合并到 | 理由 | 置信度 |
|---|---|---|---|---|
| `<sha>` | `<subject>` | `<sha>` | 同功能 review | high |
| `<sha>` | `<subject>` | `<sha>` | 设计文档细化 | medium |

### 4. 重放方式

| 方式 | 适用 | 注意 |
|---|---|---|
| `git rebase -i` + fixup | 提交连续、冲突少 | 中途冲突要逐个解决 |
| 树快照重建（`commit-tree`） | 分组跨越大、需要精确控制 | 每组取组内最后一个 tree |
| `git reset --soft` + 重新提交 | 只想压成少量提交 | 会丢失中间结构 |

### 5. 时间与作者

- 合并组取组内**最早**提交的 author date
- 同时设置 `GIT_COMMITTER_DATE`，避免 log 显示当前时间
- 保留原作者信息；多作者时取组内最早者

### 6. 校验清单

```bash
git diff <整理前 HEAD> HEAD        # 只允许预期差异
git log --oneline | wc -l          # 提交数符合目标
git fsck --no-progress
<构建命令> && git status           # 生成物无变化
<CI 命令>
```

- 若生成物有变化，说明对应提交未同步 lock/清单
- 若树差异包含非预期文件，回退重放

### 7. 反模式

| 反模式 | 后果 |
|---|---|
| 把所有提交压成一条 | 丢失可读历史与 bisect |
| 跨功能强行合并 | 审查困难，回滚粒度变粗 |
| 把结构性重构塞进功能提交 | 无法单独回滚 |
| 重写已共享分支但不通知 | 他人历史分叉 |
| 不带 lease 的 force push | 覆盖他人提交 |

### 8. 本仓库落地（示例）

- 生成物 `project/assets.lock.toml` 跟随 cnb 二进制变更
- 组件首次入库（bksmartpacker）保留并附 `NOTICE`
- 结构性重构（目录/命名/分层）单独提交
- 文档里程碑独立，细化并入里程碑
- 历史整理后入口文档仍为 `docs/README.md`
